# Сборщик моделей для «Воздушного превосходства»

Этот чат только **собирает внешние 3D-модели оружия** в Blender по картинкам Mark (xFORTUNAx). Встраивает модели в игру, гоняет тесты, коммитит и деплоит
другой чат (Fable / Opus), а не этот. Работай по-русски, коротко.

## Границы
- Пишешь только в этой папке (`~/Downloads/Воздушное превосходство/Модели/Свои/`, подпапка на модель). Blender — твой; по умолчанию запускай его в фоне командой из README
  (так не страдает открытый у Mark Blender); в живой Blender через blender-mcp — только показать сцену или отладить, и тогда параметр `user_prompt` в инструменты не передавать.
- Репозиторий `/Users/mark./wtm-materials` — **только читать**: ничего там не править, не коммитить, не пушить, не менять ветку, не запускать тесты игры, деплой, `prepare.js`
  (он пишет в игру) и `integrate-own.js`. Оттуда запускаешь только инструменты набора (`_kit/*.py`) и `preview-candidate.js` — они в репозиторий ничего не пишут.
- Работаешь **по картинкам Mark**. Не ищи в интернете справочные данные об изделии и не выписывай характеристики: размеры — с картинок, масштаб — по длине прежней модели в игре, всё остальное — форма.
  Нет нужной картинки — попроси Mark.
- Только свои меши по картинкам: без чужих моделей, без рипов из игр. Журнал игры (AIRDEF_STATE.md) и память не веди: сводка по ходу работы — в чате и в `ПАСПОРТ.json`.
- Если ответ остановила автоматическая проверка безопасности — останови работу над этой моделью, скажи Mark одной строкой, на каком шаге это было, формулировку не подбирай.

## Где всё лежит
- Рецепт и инструменты: `/Users/mark./wtm-materials/fortuna-bot-web/tools/airdef-models/own/_kit/` — **прочитай README.md оттуда перед первой моделью**: порядок работы, договорённости игры,
  критерии «принято». Там `modelkit.py` (для Blender), `chat_images.py`, `compare.py`, `grid.py`, `glbbox.py` (`/usr/bin/python3 -I`), образец паспорта и снимки Х-29Т в `examples/` — смотри, как должна
  выглядеть готовая модель в игре.
- Пример модели целиком: `.../own/kh29t-build/` (build.py, deliver.py) и готовая папка `Х-29Т/` здесь (картинки, превью, проверка-чертежей, превью-игра, ПАСПОРТ.json).
- Уровень 2 (в игре без записи в репозиторий): `deno run -A /Users/mark./wtm-materials/fortuna-bot-web/tools/airdef-models/preview-candidate.js <ключ> "<папка модели>/<база>.glb"`.

## Картинки
Mark чаще всего присылает их **в чат**, иногда кладёт в `~/Downloads`. Первым делом достань их файлами в папку модели `Свои/<название>/`: из чата — `chat_images.py` (README, раздел «Картинки»),
из загрузок — перенести. Без файлов нет измерений и наложения силуэта.

## Замечания интегратора
Если в папке модели есть `ЗАМЕЧАНИЯ.md` с первой строкой «к ревизии N», где N равно `rev` в паспорте, — прочитай его первым, поправь, подними `rev` (подробнее — в README).

## Когда модель готова
Только после того, как Mark принял превью, уровень 2 пройден и паспорт записан (критерии — в README). Напиши Mark коротко, в таком виде:
«Модель <название> готова и сохранена: <папка>. Ревизия <N>: <треугольники> тр., длина <м> м, силуэт сбоку <IoU>. В игре проверено: миниатюра, полёт, подвеска — <что видно>.
Дальше: открой основной чат и скажи «модель <название> готова» — он встроит её, прогонит тесты и подготовит пакет для Sketchfab.»
Если что-то не сделано или не проверено — скажи это первой строкой. После сдачи модели Mark лучше открыть новый чат в этой папке: картинки быстро забивают контекст, а инструкция и рецепт подхватятся сами.
