# Сборка внешних моделей оружия — рецепт сборщика

Для чата сборщика (Sonnet 5.5) и для всех, кто будет дорабатывать такие модели. Пример целиком — Х-29Т: `../kh29t-build/` (build.py, deliver.py, паспорт),
результат `../kh29t.glb`, снимки `examples/`. Образец лежит в репозитории только потому, что Х-29Т уже встроена: **свою модель сохраняй в папку модели
`~/Downloads/Воздушное превосходство/Модели/Свои/<название>/`, не в репозиторий.**

## Что строим
Только **внешнюю форму** по картинкам Mark (вид сбоку, спереди, сзади, схема окраски): закрытые оболочки, швы и лючки как рельеф, без внутренностей и без текстур.
Справок об изделии не ищем и не записываем: размеры берём с картинок, масштаб — по длине прежней модели в игре.

## Картинки: откуда брать
1. **Mark прислал их в чат.** Они сохраняются в журнале чата, и скрипт достаёт их файлами в полном качестве (проверено: побайтно как оригиналы):
   `/usr/bin/python3 -I chat_images.py "<папка модели>"` (по умолчанию — картинки из последнего сообщения Mark с картинками; `--all` — все; `--list` — только перечислить).
   Запускать из папки чата сборщика. Файлы получат имена 1.png, 2.jpg …
2. **Лежат в `~/Downloads`.** `ls -t ~/Downloads | head -20`, выбрать картинки по времени и описанию Mark, перенести в папку модели (правило Mark: скачанное после использования лежит в тематической папке).
3. Нет ни того, ни другого — попросить Mark прислать. Работать «на глаз» по картинке в чате можно только для первого наброска: без файлов нет измерений и наложения.
Записать в `build.py` комментарием, что на какой картинке (1 — бок, нос слева; 2 — спереди …). Фотографии (перспектива) годятся для пропорций; IoU — только для чертежей с ортогональными видами.

## Договорённости игры
- **Оси и единицы.** Метры. Нос — +Y в Blender (в glTF уйдёт в −Z, `nose: '-z'` в prepare.js). Начало — середина длины. Верх при подвеске — +Z (проушины сверху, кожух снизу).
  Расположение оперения — как на картинках (у Х-29Т крестом ×, плоскости под 45°). Нос на чертеже справа — `configure(nose='right')`.
- **Имена.** База файла = ключ модели без `w_`, строчными латиницей: `kh31p.glb`, `kh31p.blend`. Сцена и коллекция в Blender — база заглавными (`KH31P`), материалы и объекты —
  короткий префикс (`K31_body`, `K31_wing`, `K31_ctrl`, `K31_dark`). Кириллица и пробелы в именах файлов модели ломают путь в prepare.js (скрипт встраивания это не пропустит).
- **Длина.** Как у прежней модели в игре: `/usr/bin/python3 -I glbbox.py /Users/mark./wtm-materials/fortuna-bot-web/games/airdef/models/<ключ>.glb`
  (нос в −Z, длина по z, допуск ±3 %). Радиус и пропорции — с картинок. Ключ и оружие — строка в `models.js` (`grep -n "<оружие>"`): `w_kh31p: { weapon: 'kh31p', … }`.
- **Материалы.** Не больше четырёх, цвета линейные (prepare.js читает baseColor как есть), без текстур. Светлый серо-белый корпус, тёмные швы, купол и сопло — как у Х-29Т;
  другая окраска — по картинке и слову Mark. Цвет и форму правит сборщик (интегратор присылает замечание), в prepare.js цвет для своих моделей не переопределяется.
- **Бюджет.** 3–6 тыс. треугольников, файл до ~200 КБ. Не ужимать «сильно»: форму держат сегментами тела вращения (32), а не децимацией.
- **Нормали.** Закрытые оболочки; `B.finish()` сам считает нормали наружу и помечает острыми рёбра круче 32°. Объекты — по назначению (корпус, крылья, рули, накладки, кожух), около десяти.

## Как запускать Blender: два способа
1. **Фоновый (по умолчанию).** Не трогает открытый у Mark Blender, не падает вместе с ним, результат — файлы. Из папки модели:
   ```
   K29_OUT="<папка модели>" /Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup \
       --python <папка модели>/build.py --python <папка модели>/deliver.py
   ```
   `modelkit.configure` в фоне сам начинает с пустого файла (без стартового куба). Образец `deliver.py` — `../kh29t-build/deliver.py`: силуэты, статистика, превью, экспорт, паспорт.
2. **Живой Blender через blender-mcp** — чтобы показать сцену (`look`) и править интерактивно; скрипт запускать через `exec(compile(open(p, encoding='utf-8').read(), p, 'exec'))`.
   Осторожно: **не оборачивать экспортёр glTF в `bpy.context.temp_override`** — в Blender 5.2.2 это роняло программу (журнал падения 2026-10-22, граф зависимостей). Если Blender упал:
   файлы модели на диске целы, автосохранение — в `/private/var/folders/…/T/<pid>_autosave.blend`; открыть Blender заново и нажать Start MCP Server.
   Библиотека набора перед выгрузкой проверяет, что активна сцена модели, и сама ничего не переопределяет.

## Порядок работы
1. **Картинки** в папке модели (раздел выше).
2. **Измерения.** `grid.py` — куски чертежа с сеткой координат; снять x и радиус по сечениям, положения деталей, силуэты крыльев. Все числа — в пикселях чертежа в `build.py`;
   масштаб `S` = длина игры / длина на чертеже в пикселях.
3. **`build.py`** в папке модели на `modelkit` (образец — `../kh29t-build/build.py`): профиль вращения со швами (`profile`, `circ`), пластины (`panel`), накладки по цилиндру (`decal`, `rrect`, `ell`),
   призмы вдоль оси (`prism`: кожухи, воздухозаборники), прочее — через `B().loft`. Запуск — фоновой командой выше; исправил числа — запустил заново.
4. **Уровень 1 (без игры).** `deliver.py` рисует силуэты в кадрах чертежей; затем `compare.py` (команды — в шапке `deliver.py`) даёт наложение и IoU и сам записывает число в паспорт.
   Если у вида спереди/сзади другой масштаб — `silhouette_end(..., rb_px=<радиус корпуса на этой картинке, пикс.>)`; если ось на чертеже не в центре — `axis_px`. Красный контур — модель,
   синий — чертёж: смотреть глазами нос, хвост, крылья. Плюс `mk.stats()`.
5. **Превью.** `deliver.py` делает четыре картинки 1920 × 1080 (общий, сбоку, хвост, голова) для Mark и для Sketchfab. Показать Mark, дождаться «принимаю».
6. **Выгрузка и уровень 2 (в игре, без записи в репозиторий).** Сначала `mk.export` (в `deliver.py` он уже есть) — файл `<папка модели>/<база>.glb` должен существовать и быть свежим, потом:
   `deno run -A /Users/mark./wtm-materials/fortuna-bot-web/tools/airdef-models/preview-candidate.js <ключ> "<папка модели>/<база>.glb"` (снимки — в `<папка модели>/превью-игра/`).
   Снимает миниатюру «Исследований», полёт с факелом и подвеску под самолётом; в сводке — сколько раз игра взяла кандидата (0 — сцена показывает другую модель). Быстрый круг без подвески:
   `--scenes thumb,plume`. Правка — в `build.py`, затем снова пункты 4–6 (с выгрузкой).
7. **Сдача.** В папке модели: `<база>.glb`, `<база>.blend`, `build.py`, `deliver.py`, превью, `проверка-чертежей/`, `превью-игра/`, `ПАСПОРТ.json` (поля — `passport.example.json`; блок `sketchfab` —
   только форма и сборка модели; в `checks.game` словами: что видно в миниатюре, полёте и на подвеске). Сообщить Mark, что модель готова и где сохранена.

## Когда считать «принято»
- Mark сказал «принимаю» по превью (пункт 5).
- Уровень 1: силуэт сбоку ≥ 0,95; вид спереди и сзади ≥ 0,85 (если есть такие чертежи); длина в пределах ±3 % от прежней модели; ≤ 6 тыс. треугольников, ≤ 4 материалов, файл ≤ ~200 КБ.
- Уровень 2: во всех сценах «кандидат взят», ошибок страницы нет; ракета на подвеске не торчит и не тонет, цвет не выбивается из семейства оружия, факел выходит из сопла.
- Паспорт записан, `rev` указан.

## Если интегратор вернул замечания
Файл `ЗАМЕЧАНИЯ.md` в папке модели (пишет основной чат; первая строка «к ревизии N»). Брать в работу, только если N равно `rev` в паспорте. Поправить `build.py`, поднять `rev` на единицу,
заново пройти пункты 3–7 и сказать Mark, что ревизия готова; замечания к прошлой ревизии считаются закрытыми.

## Файлы набора
| Файл | Для чего | Где запускать |
|---|---|---|
| `modelkit.py` | профиль вращения, пластины, призмы, накладки, статистика, силуэты, превью, экспорт, паспорт | Blender (фоновый или blender-mcp) |
| `chat_images.py` | картинки из чата → файлы | `/usr/bin/python3 -I` |
| `compare.py` | наложение силуэта на чертёж, IoU, запись в паспорт (нужны Pillow и numpy) | `/usr/bin/python3 -I` |
| `grid.py` | куски чертежа с сеткой координат (Pillow) | `/usr/bin/python3 -I` |
| `glbbox.py` | габариты и число треугольников glb | `/usr/bin/python3 -I` |
| `passport.example.json` | образец паспорта (Х-29Т) | — |
| `examples/` | снимки Х-29Т: превью, наложение, миниатюра, полёт, подвеска (подвеска — JPEG, сам инструмент пишет PNG) | смотреть |
| `../kh29t-build/` | образец: `build.py`, `deliver.py`, паспорт | Blender |
| `../../preview-candidate.js` | уровень 2: кандидат в настоящей игре | Deno + Chrome |

Заметка про общую видеокарту: превью игры (Chrome с GPU) и тесты интегратора лучше не гонять одновременно — тесты, которые изредка падают и так, будут падать чаще.
Превью берёт игру из рабочего дерева репозитория как оно сейчас: если страница не открывается, интегратор, вероятно, в середине правки — повторить позже.
