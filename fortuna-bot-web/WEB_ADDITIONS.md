## 0. Важные грабли и конвенции — читать в первую очередь

- **Пользователь регулярно грузит новые ассеты не в ту ветку.** GitHub веб-интерфейс запоминает последнюю использованную ветку при загрузке файлов, и он периодически заливает SVG/картинки в `fortuna-web-game` вместо `main`, хотя работа идёт в `main`. Стандартное восстановление:
  ```bash
  git fetch origin fortuna-web-game
  git show origin/fortuna-web-game:fortuna-bot-web/UI/имя_файла.svg > /tmp/имя_файла.svg
  ```
  Не мёржить эту ветку целиком — там же лежит отдельный 3D-проект `fortuna-game` (Battle_Base_Clan_Wars, .glb модели), не относящийся к сайту.
- **Деплой edge-функции**: `supabase functions deploy <имя> --no-verify-jwt` из `fortuna-bot-web/`. Несмотря на `--no-verify-jwt`, шлюз Supabase всё равно требует заголовки `Authorization: Bearer <anon-key>` **и** `apikey: <anon-key>` — это уже учтено во всех клиентских вызовах (`js/api.js: callEdgeFunction`).
- **SQL-миграции** в папке `sql/` — не через `supabase migration`, а напрямую: `supabase db query --linked --workdir . < sql/0XX_name.sql`. Применять сразу после создания файла, не откладывать.
- **Проверка деплоя GitHub Pages**: кэш-бастинг обязателен (`?cb=$(date +%s)`), и либо `-L` (следовать редиректу с `github.io` на кастомный домен), либо сразу дёргать `fortunawtm.com` напрямую — иначе можно словить ложный "ещё не задеплоилось".
- **Тестовые аккаунты**: регистрировать через `auth-password` (`{"action":"register","login":"...","password":"..."}`), тестировать, затем **обязательно удалять** в правильном порядке внешних ключей: `activity_feed` (по `target_player_id`) → `player_items`/`player_equipment` → `player_economy` → `players`. Тестовые логины в этой сессии имели суффиксы вида `test1`, `arcadetest1` и т.п. — при поиске "забытых" тестовых записей проверять по этому паттерну.
- **z-index при декоративных слоях**: если позиционируешь `<i class="theme-point">` или похожие элементы с `z-index: -1/-2` внутри карточки, у САМОЙ карточки обязательно должен быть свой `z-index` (например `1`), иначе декоративный слой проваливается под фон всей страницы, а не только под фон карточки — реальный баг, словленный и починенный при адаптации тем профиля (см. §4).
- **Локальное тестирование через `python3 -m http.server`**: браузерная вкладка агрессивно кэширует статические JS/CSS/HTML даже при повторной навигации на тот же URL в рамках одной сессии тестирования — после правки файла на диске старую вкладку нужно либо жёстко перезагружать (Cmd+Shift+R), либо открывать свежую вкладку, а не просто `navigate()` в ту же.

## 1. Иконки (`js/icons.js`)

Три источника в одном файле, у функции `icon(name, sizePx)` порядок проверки: `_ICON_IMAGES` (PNG) → `_ICON_PATHS_64` (viewBox "0 0 64 64" или похожий) → `_ICON_PATHS_512` (viewBox "0 0 512 512", самый частый случай для новых иконок) → `_ICON_MARKUP_24` (рукописные, только `fortress` остался).

Новые SVG-ассеты обычно приходят как «чёрный квадрат-фон + один путь с реальной иконкой» — извлечение: `re.findall(r'<path d="([^"]+)"', svg)`, `paths[0]` — фон, выбросить, `paths[1]` — нужный путь.

Иконки, добавленные в этой серии сессий (в `_ICON_PATHS_512`): `carKey`, `commercialAirplane`, `fragmentedMeteor`, `jetFighter`, `stopwatch`, `chatBubble`, `hazardSign`, `share`, `chest512`, `laurelCrown`, `magnifyingGlass`, `cardRandom`, `battleship`, `ticket`.

`iconVal(name, sizePx, valueHTML)` — оборачивает иконку+значение в `<span class="icon-val">` (inline-flex) — нужно, потому что PNG и inline-SVG иконки иначе по-разному считают vertical-align относительно baseline текста и "разъезжаются" по вертикали при смешивании с текстом.

## 6. Аркада (вкладка «Игра» → секция «Аркада»)

Два мини-игры из `/Users/mark./wtm-materials/fortuna-game/minigames/` (`strat.html` — Стратег, `sea.html` — Морской бой), скопированы в `fortuna-bot-web/games/` **с лёгкой правкой**: добавлен `TRAINING_MODE` (по `?mode=training` в URL) и честный текст награды в модалке победы (было захардкожено "+50 деталей · +50 XP · +5 редких" от исходного проекта — заменено на актуальный текст или "без наград" в зависимости от режима).

Игры **уже были спроектированы** под встраивание — сами шлют `window.parent.postMessage({type:'mg_win', game:'strat'|'sea'}, '*')` при победе и зовут `window.parent.closeMgOverlay()` при выходе. Родительская сторона (`js/app.js`):
- `#arcade-overlay` — полноэкранный `<iframe>` (`position:fixed; inset:0; z-index:200`).
- `window.closeMgOverlay` — глобальная функция (обязана быть на `window`, её вызывает iframe).
- `window.addEventListener('message', ...)` — слушает `mg_win`, проверяет `e.source === iframe.contentWindow` (защита от левых сообщений), и **только если игра была в ranked-режиме** — зовёт `claim-arcade-reward`.

**С введением билетов (§12) кулдаун 24 ч убран** (колонки `last_strat_win`/`last_sea_win` остались в схеме, но не используются). Партия на награду = 1 билет: клиент зовёт `start-game-run` (списывает билет, отдаёт `run_id`), при победе — `claim-arcade-reward` с этим `run_id`. Победа даёт случайно **2 ключа или 2 детали**; `run_id` работает один раз, не раньше чем через 25 с после старта и не позже чем через 3 ч. Тренировочный режим (`?mode=training`) бесплатен и награду с бэкенда никогда не запрашивает. В режиме на награду в играх убраны «Сыграть снова»/«Реванш» — иначе это бесплатная вторая попытка на тот же билет.

## 8. Производительность

Жалоба пользователя: "всё долго грузится и фармится". Две независимые причины, обе исправлены:

1. **Клиент**: раньше клик по ЛЮБОЙ вкладке нижней навигации вызывал полный `renderDashboard()` → повторный `getPlayerState` по сети → вспышка "Загрузка..." — хотя простое переключение вкладки не меняет состояние игрока. Исправлено: `switchTab(tabId)` просто перерисовывает `#tab-content` из уже загруженного `currentState`, без сети. `renderDashboard()` (с реальным рефетчем) вызывается только после действий, которые действительно меняют экономику.
2. **Бэкенд**: почти все edge-функции делали 6–9 **последовательных** обращений к Postgres (отдельный `hasItem()` на каждый проверяемый предмет вместо одного `ownedSlugs()`, лишние повторные select после update и т.д.). Переписаны на `Promise.all` там, где запросы независимы — большинство функций теперь укладываются в 3 последовательных "шага" вместо 6–9. Затронуты: `farm-loot`, `farm-fireball`, `farm-radiofugas`, `farm-meladze`, `shop-buy`, `equipment-craft`, `container-open`, `minigame-spin`.

## 12. Билеты на игры с наградой

- **5 билетов в день**, обновление раз в сутки (граница — полночь МСК), неиспользованные не копятся. В интерфейсе вместо времени сброса показывается **живой таймер обратного отсчёта** (`liveCountdown`). Лимит — константа `DAILY_TICKETS` в `supabase/functions/_shared/tickets.ts` (сервер отдаёт её клиенту как `daily_tickets` в `get-player-state`, дублировать число в клиенте не нужно).
- Тратят билет: слот Фортуны (`minigame-spin`; **по-прежнему максимум 3 попытки в день** и цена в монетах сверх билета), Стратег и Морской бой (`start-game-run`). Тренировки бесплатны. Дрон-игра (§13) и общая недельная цель — в разработке, тоже будут на билетах.
- Списание атомарное: SQL-функция `spend_ticket(player, daily)` — один `UPDATE` с условием, поэтому параллельные запросы не пробивают лимит (проверено: 8 одновременных стартов при 5 билетах → ровно 5 успешных). Если слот списал билет, а следующий апдейт упал — вызывается `refund_ticket`.
- `start_game_run(player, game, daily)` — билет + строка в `game_runs` в одной транзакции; в строке же лежит `seed` (пригодится дрон-игре для детерминированных волн и серверной оценки максимально возможного счёта).
- **Граница суток — МСК везде**: билеты и `spin_day` слота (раньше слот сбрасывался по UTC, т.е. в 03:00 МСК). Клиентские хелперы `mskDate()` / `secondsUntilMskReset()` в `js/app.js`.
- Интерфейс: строка «Билеты на игры» с полосками под статами, значок `ticket` (из присланного `ticket.svg`), «+1 билет» в цене слота, «Партия на награду: 1 билет» в аркаде. Админ-панель умеет сбрасывать билеты (`tickets` в `admin-reset-cooldowns`).
- Открытая (проигранная/брошенная) партия остаётся в `game_runs` со статусом `open` — билет не возвращается, это осознанно. При удалении тестового игрока `game_runs` чистится каскадом (`on delete cascade`), но в списке порядка FK из §0 его всё равно стоит удалять явно перед `players`.

## 13. Симулятор Летки (бывш. «Дрон-перехватчик» → «Ударный дрон»; `games/drone.html` + `games/drone/*.js`) — 3D-игра, прототип v3

> **Статус на 2026-09-29:** v3 написана и владелец её запускал (обратная связь: мало/много дронов → переделано на ИИ-самолёты; «ракета висит на 3,7 км» → см. «Энергетика ракет»). Итерации 2–4 (режимы, клавиши, руководство, динамика «Изделия»; обучение, адаптация, сверхзвук, переименование; линейный цвет, конвейер кадра, апскейлеры, погружение, звук, анимации) прогнаны headless-тестом (`tools/drone-headless/run.sh`, все 5 пресетов + обучение — без ошибок выполнения), но **шейдеры и картинка в браузере не проверены** (JavaScriptCore) — браузерная панель в той сессии была заблокирована. Перед коммитом: открыть `http://localhost:8934/fortuna-bot-web/games/drone.html?mode=training&test=1`, проверить консоль, меню (4 вкладки + переключатель режима), назначение клавиш, полёт, ИИ, тест графики; прогнать бота через `window.__g.tick()`. Предыдущая рабочая версия (v2, один файл) — в коммите `95d6a2f`.

Игрок — ударный беспилотник «Изделие Фортуна-1» (вид от третьего лица), противник — вымышленные беспилотные истребители «Подстилки улитки» под управлением ИИ. Вылет до 5 минут, арена радиусом 12 км (карта ~34×34 км с хребтом по краю), реальные по порядку скорости (крейсер ~250 м/с, форсаж до ~М1,6 на высоте). three.js **r128** с cdnjs + ES-модули (`<script type="module" src="drone/main.js">`), внешних ассетов нет.

**Файлы (`games/drone/`):**
- `schedule.js` — `SCHEDULE_VERSION = 2`, `H_CAP = 300`, `UNIT_KILLS`, `mulberry32`, `buildSchedule(seed)`, `maxKills`. Чистые функции без DOM/three — **сервер (Deno) может импортировать файл как есть**. Любое изменение логики — только через новую версию. v2: 4 группы (2 «Слизня» → 2–3 «Слизня»/«Раковины» → «Ас» + 1–2 → флагман + 2 эскорта) и 4 танкера; `maxKills` ≈ 12–16. **Прежняя v1 (103 дрона за 120 с) больше не используется** — решение владельца, т.к. серверной проверки ещё не было.
- `missiles.js` — каталог 22 УРВВ в 4 группах (ранние: AIM-9B, Р-3С, Firestreak, AIM-7E; ближний бой: Р-60М, AIM-9L, Р-73, AIM-9X, IRIS-T, Python-5; средняя: AIM-7M, Р-27Р/Т/ЭР, MICA EM/IR, Derby, AIM-120C, Р-77; большая: Р-33, AIM-54, Meteor). У каждой — история, принцип наведения, реальные ТТХ (открытые данные, «≈»), игровые параметры (кинематика, ГСН, помехозащищённость, БЧ) и параметры модели `vis`.
- `models.js` — процедурные модели (склейка в один меш): дрон игрока с 8 пилонами (законцовки ≤110 кг, средние ≤200, корневые ≤360, подфюзеляжные ≤500, всего ≤1500 кг) и подвижными элевонами; генератор ракет по `vis` (решётчатые рули Р-77, гранёный нос Firestreak, воздухозаборники Meteor, «бабочки» Р-27…); 4 типа «улиточных» самолётов с раковиной-горбом и глазами на стебельках; танкер со шлангом и корзиной.
- `world.js` — рельеф (`terrainH`, ровные площадки под 4 города и аэродром, река), здания с окнами (шейдер), лес, облака, небо, карта окружения для PBR, шейдерные частицы (с логарифмической глубиной). Всё зависит от пресета графики.
- `main.js` — всё остальное (см. ниже). Отладочный хук `window.__g` при `?mode=training&test=1`.

**Механики:**
- Лётная модель общая для игрока и ИИ: угловая скорость ограничена перегрузкой (`gmax·g/v`), индуктивное сопротивление в вираже, тяга падает с высотой, сваливание на малой скорости. Масса и число ракет снаружи влияют на разгон/сопротивление и **ЭПР игрока** (1 + 0,15 м² за ракету).
- Ракеты: ускорение/время работы двигателя/сопротивление/перегрузка → реальная энергетика (дальше на высоте). **Зона пуска (Rmax / неизбежная зона / Rmin) считается той же кинематикой** (`dlz()`), показывается у захваченной цели и шкалой на индикаторе РЛС. ИК — захват ГСН по тепловой заметности (форсаж ×2,2, в лоб ~40%), ракурсные ограничения ранних ГСН, «увод на солнце», захват после пуска у новых; ПАРЛ — подсвет до попадания; АРЛ — радиокоррекция пока РЛС видит цель, затем «питбуль», наведение на источник помех. Неконтактный взрыватель по точке наибольшего сближения, урон спадает с расстоянием.
- Радар игрока: обзор ±60°×±35°, дальность ∝ ЭПР^¼ (36 км для 5 м²), доплеровский провал, РЭБ флагмана (прожиг 16 км), масштаб 10/20/40 км, пуск АРЛ по отметке обзора (противник не получает предупреждения о захвате).
- **СПО** (круг слева внизу): пеленги чужих РЛС, режимы обзор/захват/пуск, «М» — активная ГСН ракеты. **Датчик пуска ракет** видит факел работающего двигателя (в т.ч. ИК-ракет, которые СПО не видит). Звуковые сигналы разные для захвата и пуска.
- **ЛТЦ** (32) и **диполи** (32): шанс увода зависит от помехозащищённости ракеты, форсажа (ЛТЦ) и доплеровского провала (диполи); диполи также срывают захват РЛС. ИИ пользуется тем же.
- ИИ: радар с собственной дальностью и провалом; пуск между неизбежной и максимальной дальностью (зависит от «умения»); «крэнк» после пуска, чтобы держать подсвет; оборона — выход на траверз со снижением, контрмеры, резкий доворот в конце; ближний бой с упреждением, ИК-ракеты и пушка; уход от земли и границы. Флагман держит дистанцию, эскорт летит строем до сближения.
- Топливо ~190 с (форсаж ×3), 4 танкера: пролёт через корзину (≤32 м) = +70 с. Сбитые самолёты падают горящими обломками; загнанный в землю ИИ засчитывается.

**Пресеты графики** (`PRESETS` в `main.js`, выбор в меню «Графика», хранится в `localStorage` `fortuna_drone_gfx`, смена = перезагрузка): Низкий (разрешение ×0,8 ≤1, Lambert, мало деревьев/облаков), Средний (PBR + окна + детализация земли + инверсионные следы), Высокий (сглаживание, тени, 6000 деревьев, 40 облаков). По умолчанию: телефон — Низкий, ПК — Средний. **Тест графики**: отдельная тяжёлая сцена рендерится ~2,6 с с параметрами каждого пресета, по средним кадрам/с и худшим 5% кадров — рекомендация (`fortuna_drone_bench`).

**Протокол с родителем:** `mg_result` теперь содержит `schedule_version: 2`, `max_kills`, `evaded`, `missiles_fired`, `missile_hits`, `loadout`; `reason` ∈ `hull`/`fuel`/`time`/`win`.

**Режимы** (`MODES` в `main.js`, переключатель над вкладками меню, `localStorage` `fortuna_drone_mode`, по умолчанию «Аркада»): физика ракет/радара/СПО одинаковая, различаются подсказки и прощение ошибок. Аркада — все ракеты противника на HUD с дистанцией и сближением, перегрузка 15 g, вдвое меньше потеря скорости в вираже, почти без сваливания, урон ×0,5, ИИ ×0,7 по «умению», 48 ЛТЦ/диполей, сильное доведение пушки, захват ГСН 0,25 с, топливо ×1,4, корзина 60 м. Реализм — только датчик пуска (горящий двигатель) и активная ГСН, 12 g, полная энергетика, урон ×0,9, опытный ИИ, 32/32, захват 0,5 с, корзина 32 м, **очки ×1,5**. Режим уходит в `mg_result` полем `mode` — пороги наград на сервере, вероятно, нужно делать по режиму.

**Энергетика ракет.** Двигатель работает 2–10 с, дальше ракета тормозится. Раньше «выдохшаяся» ракета могла долго висеть за целью почти с её скоростью и догнать, как только цель поворачивала (жалоба владельца: «дистанция держится на 3,7 км, а потом прилетает»). Теперь: скорость сближения считается каждый кадр; если после выгорания ракета не догоняет (сближение < 15 м/с) дольше 2,5 с — цель потеряна, через 1,5 с самоликвидация; порог неуправляемости — max(220 м/с, 0,75·vmin). На HUD у каждой летящей в игрока ракеты — «догоняет N м/с · T с» или «НЕ ДОГОНЯЕТ» (надпись угрозы и красные метки).

**«Изделие Фортуна-1»** (так теперь называется дрон игрока): тяга 16/34 м/с² (было 13/27), сопротивление ниже, быстрый отклик (agil 8–11, крен 9), перегрузка 12/15 g по режиму. Камера уходит наружу виража, отстаёт при перегрузке, тряска на больших g/околозвуке/форсаже, FOV растёт со скоростью, «толчок» при включении форсажа, конус конденсата около М1, вихри с законцовок от 4 g, «взгляд назад» (V).

**Назначение клавиш (ПК).** `ACTIONS` в `main.js`: 17 действий, по два слота, кнопки мыши — коды `Mouse0/1/2`; настройка во вкладке «Настройки» (клик по ячейке → клавиша или кнопка мыши над таблицей; Backspace — очистить; одна клавиша — одно действие), сохраняется в `fortuna_drone_keys`. Там же: управление мышью вкл/выкл, инверсия, чувствительность (`fortuna_drone_mouse`). Esc всегда пауза.

**Меню:** вкладки «Подвеска», «Ракеты», «Руководство» (13 глав: быстрый старт, ход вылета и очки, полёт и энергия, HUD, радар и масштаб, ракеты и зона пуска, стрельба по шагам, СПО, уклонение против каждого типа ракет/пушки/флагмана, противник, дозаправка, сравнение режимов, советы по подвеске), «Настройки» (графика + тест, управление).

**Режим «Обучение»** (`MODES.training`, раздел «Режим «Обучение»» в `main.js`; доступен только при `?mode=training` — в партии на награду кнопка неактивна). Вместо волн расписания — «режиссёр» `trainingTick`: берёт все 22 ракеты в случайном порядке; для каждой создаёт учебный носитель там, откуда такую ракету пускают на самом деле (ИК — сзади-сбоку в пределах дальности ГСН, ранние — строго в хвост; радиолокационные — спереди между неизбежной и максимальной дальностью), даёт 2–3 с на захват (виден на СПО) и пускает. Над HUD — короткие подсказки по ходу полёта ракеты (что делать и какую кнопку нажать; дистанция, пеленг, «догоняет/не догоняет»). Окошко «?» (кнопка или `KeyH`) → пауза и объяснение ракеты: что это, как её заметить, что делать по шагам, кнопки, текущая ситуация. После пуска — разбор по причине промаха (`m.why`: `flare`/`chaff`/`notch`/`energy`/`gimbal`/`sun`) или попадания, затем носитель можно сбить (подсказки атаки), через 25 с — следующий пуск. При смене своей ракеты — «?» с инструкцией, как ей стрелять, и текущими дальностями. Корпус восстанавливается, топливо не тратится, ракеты и ловушки перезаряжаются, результат на сервер не отправляется.

**Интерфейс под устройство.** `ctl(action)` возвращает название нужной кнопки: на ПК — назначенные клавиши (`<kbd>`), на сенсорных — экранные кнопки. Им пользуются руководство (перерисовывается при смене клавиш), подсказки и объяснения обучения. Положения индикаторов в текстах — из `POS` (на телефоне РЛС и СПО вверху). Классы `body.coarse` (сенсор), `body.narrow` (< 700 px), `body.short` (< 520 px по высоте, телефон в альбомной ориентации) перестраивают HUD, кнопки и карточки. На сенсорных добавлены «ГАЗ−» (малый газ, нужен для заправки) и «НАЗАД» (взгляд назад).

**Пресеты «Ультра» и «Кино»** (`games/drone/post.js`): сцена рендерится в HDR-буфер (HalfFloat, MSAA ×4 на WebGL2), bloom в двух масштабах, тонмаппинг ACES, виньетка; «Кино» — плюс киноцветокоррекция, зерно, хроматическая аберрация, разрешение до 2,5×. Также тени 4096, живая вода (возмущение нормали бегущими волнами), блики объектива (DOM-слой `#flares`, гаснут, если солнце за рельефом), до 14 000 деревьев и рельеф 520². Тест графики теперь 5 фаз (~15 с): рекомендация — самый высокий пресет, держащий ≥ min(55, 0,9 × частота экрана) к/с.

**Сверхзвук.** При переходе М1 — хлопок (низкий удар + треск), кольцо ударной волны (остаётся в воздухе и расходится), облако конденсата, тряска и «толчок» камеры, надпись «СВЕРХЗВУК». На сверхзвуке звук другой: вой турбины глохнет, рёв уходит в низкий рокот (полоса 500 → 170 Гц), главным становится свист обтекания; при возврате ниже М0,97 — «ДОЗВУК».

**Цвет и конвейер кадра (итерация 4).** Линейный цвет во всех пресетах: авторские sRGB-цвета переводятся в линейные (`lin()` в `world.js`, `convertSRGBToLinear` в `mergeParts`), освещение физическое, на выходе ACES + sRGB. Без конвейера это делает `renderer` (`toneMapping = ACESFilmic`, `outputEncoding = sRGB`, только «Низкий»); с конвейером — `games/drone/post.js` (`createPipeline`): HDR-буфер (HalfFloat, MSAA ×4 на WebGL2) в масштабе рендера → свечение → лучи от солнца («Кино», радиальное размытие) → композит (ACES, цветокоррекция, виньетка, зерно, P3, гамма) → FXAA → апскейл CAS или FSR-стиль (Lanczos-2 с ограничением против ореолов + RCAS). Небо — шейдер (зенит/горизонт, дымка у солнца, HDR-диск), отражения PBR берутся из него же. «Высокий» и выше: объёмные облака из освещённых спрайтов (`InstancedBufferGeometry`, «серебряная кромка» против солнца); облака стоят на максимумах `cloudField()`, и та же функция в шейдере земли рисует их тени (со сдвигом по направлению солнца). «Ультра»/«Кино»: земля на `MeshStandardMaterial` с микрорельефом (шумовая нормаль, гаснет с расстоянием), тени 4096 на ±400–450 м, свет от форсажа и двух ближайших горящих ракет. Лес — квадраты 2×2 км (свой `InstancedMesh` и `boundingSphere`, отсечение вне кадра и дальше `treeDist`), дома — отдельный `InstancedMesh` на город.

**Производительность (вкладка «Настройки»).** `perf` в `main.js` (хранится в `fortuna_drone_perf`, при смене пресета — умолчания пресета из `PRESETS[*].perf`): цель к/с 30/60/120, динамическое разрешение (каждые 0,5 с: кадр медленнее цели → масштаб −0,04…−0,1, быстрее → +0,03, в пределах `min…scale`), масштаб рендера (пресеты FSR 50/59/67/77%), апскейлер Выкл/CAS/FSR + резкость, сглаживание Выкл/FXAA/MSAA, ограничение кадров, широкий цвет P3 (если экран и браузер умеют), счётчик кадров. У каждого пункта — пояснение. **Сравнение апскейлеров**: натив 100%, 67% без апскейлера, 67% + CAS, 67% + FSR — замер к/с и снимок кадра каждого, окно со «шторкой», увеличением ×2 и таблицей прироста. Тест графики учитывает `perf` пресетов. HUD облегчён: тексты, полосы, радар и СПО — 15 раз/с, метки на экране — каждый кадр.

**Режим погружения** (`enterImmersive`, по умолчанию включён, запускается кликом «ВЗЛЁТ»): полный экран с `navigationUI: 'hide'`, захват мыши (Pointer Lock — рулёжка виртуальным курсором по `movementX/Y`, курсор не уедет на панели браузера), `navigator.keyboard.lock()` в полноэкранном Chromium, Wake Lock, фиксация ориентации (Android), «Назад» ставит паузу (`history.pushState` + `popstate`), закрытие вкладки во время вылета — с подтверждением, блок жестов масштабирования/прокрутки/выделения. Выход из полного экрана или захвата → пауза. На iPhone Safari полноэкранного API для страниц нет — подсказка «На экран «Домой»». Фрейму аркады на сайте добавлено `allow="fullscreen; screen-wake-lock; autoplay; gamepad" allowfullscreen` (`app.html`).

**Звук.** Общая шина: компрессор + свёрточная реверберация (сгенерированный импульс). Сверхзвук: вместо шипения — приглушённая турбина (фильтр закрывается), низкий гул корпуса (46/69,5 Гц), мягкий «дышащий» поток воздуха (НЧ-шум с медленной модуляцией); хлопок — N-образная волна (два глухих удара через 0,12 с) с эхом. **Вражеские самолёты и ракеты** — 5 голосов объёмного звука (Panner HRTF, затухание с расстоянием, эффект Доплера по скорости сближения), отдаются ближайшим источникам раз в 0,25 с; у флагмана — ниже и громче, у ракеты — свист горящего двигателя.

**Анимации.** Рамка захвата «схлопывается» на цель, маркеры попаданий, сбитый самолёт разваливается (крыло и киль падают отдельно со своими шлейфами), вспышка и дым при запуске ракеты, замедление времени при сбитии флагмана, плавное появление экранов меню.

**Итерация 5 — мобильная версия, погода, оптимизация.**
- **Погода** (`WEATHERS` в `world.js`: Ясный день, Утро, Вечер, Закат, Пасмурно, Ливень): случайная на каждый вылет по весам или выбранная во вкладке «Настройки» (`fortuna_drone_weather`: `random` или ключ), в меню переключается сразу (`world.setWeather`). Задаёт высоту/азимут солнца (солнце за вылет чуть смещается — `drift`), цвет и силу света, небо (зенит/горизонт, зарево заката, дымка, диск), туман, порог облачности, воду, окна (вечером горят — эмиссия в шейдере домов, огни полосы), мокрую тусклую землю в дождь. Пасмурно и Ливень — сплошной облачный слой (один квад с шумовой текстурой, снизу серый потолок, сверху белое «море»), без теней от солнца и бликов; Ливень — капли-отрезки вокруг камеры (анимация целиком в шейдере, вытянуты по относительной скорости, выше облаков не идут), молнии (вспышка неба/облаков/света) с громом, звук дождя. «Высокий» и выше в ясную погоду — высокие перистые облака. На расписание и счёт погода не влияет; ранняя ИК-ГСН «уводится» на солнце только когда оно видно.
- **Telegram и безопасные зоны.** Внутри фрейма `env(safe-area-inset-*)` = 0, поэтому `applySafeArea()` берёт отступы у страницы-родителя и у `Telegram.WebApp` (`safeAreaInset`, `contentSafeAreaInset` — кнопки «Закрыть»/«⋯» в полноэкранном режиме) и отдаёт в CSS `--sa-t/r/b/l` и `--tg-t`. В `app.html` подключён `telegram-web-app.js` (вне Telegram ничего не делает); `/play` теперь сохраняет `search` и `hash` при переадресации (иначе терялись параметры запуска Mini App). Во время вылета: `disableVerticalSwipes` (свайп вниз не сворачивает игру), подтверждение закрытия; в режиме погружения — `requestFullscreen` и `lockOrientation` Telegram.
- **Мобильный HUD:** скорость и высота — столбиком слева над «ГАЗ−»/«НАЗАД»; окошко «?» обучения — под панелью ракет, на 25% меньше; подсказка и плашка угрозы на 20% меньше, встают в просвет между левой колонкой и СПО, угроза — под подсказкой (`placeThreat`); очки/курс/время — одной строкой; счётчик кадров выше полоски «домой». HUD поднят над слоем сенсорного управления (`z-index`) — тап по панели ракет меняет ракету (раньше тап перехватывала зона «ручки»).
- **Ручка на телефоне** (`fortuna_drone_touch`): чувствительность (радиус хода пальца), мёртвая зона, кривая отклика, инверсия тангажа — во вкладке «Настройки».
- **Счётчик кадров и динамическое разрешение.** Частота экрана меряется при загрузке пустыми кадрами (`measureRefresh`) и уточняется в полёте. Исправлено: на экране 60 Гц масштаб только падал и не возвращался (запас мощности при упоре в частоту экрана не виден) — теперь пробует подняться раз в 2 с и откатывается с паузой 10 с, если не хватило; цель 120 к/с на 60-Гц экране больше не «топит» разрешение; ограничитель кадров с допуском на дрожание меток времени (раньше мог пропускать каждый второй кадр). Счётчик: «к/с / Гц экрана · худшие 5% · масштаб», только в полёте. Меню рисуется с частотой 30 к/с.
- **Оптимизация без потери качества:** логарифмическая глубина выключена (её запись в шейдерах отключала на мобильных GPU отсечение скрытых пикселей до шейдера), вместо неё 24-битный буфер (у рендер-таргетов — с трафаретом, иначе three r128 даёт 16 бит) и ближняя плоскость 3 м; шумы земли, микрорельеф и тени облаков — выборки из текстур с мип-уровнями вместо ~40 `sin()` на пиксель (заодно вдали не «искрит»); частицы заливают в видеопамять только живой диапазон; погасшие спрайты облаков не растеризуются; деревья и дома отбрасывают тени, только когда дрон ниже 900 м; «Средний» — облегчённый 8-битный конвейер (тонмаппинг в материалах, без HDR-буфера); Lanczos апскейлера разделимый (8 весов вместо 32), лучи «Кино» — 28 выборок с дизерингом; на телефонах разрешение не выше 2×. PBR-земля «Ультра»/«Кино» была пересвечена (свет 2,4 + отражение неба 0,6) — теперь 1,9 и 0,3, экспозиция 0,95/1,0.
- **Сравнение апскейлеров:** три сцены (дрон, город с лесом, даль с облаками), масштаб ×1/×2/×4, перетаскивание картинки, щипок, колесо, двойной тап, «шторка» тянется за линию; снимки — `toBlob` (меньше памяти).
- **Тексты настроек** сокращены: у пресетов только названия, у технологий — как работает и что даёт на практике.

**Итерация 6 — звук и лобби.**
- **Звук вынесен в `games/drone/audio.js`** (`createAudio()`), в `main.js` — только привязка (`updateSound` каждый кадр). Двигатель больше не «пила» 140–400 Гц (из-за неё он звучал как квадрокоптер), а слои настоящего ТРД: рёв струи (розовый шум, спектр и громкость растут с оборотами), низкий гул (коричневый шум, «давит» на форсаже), вой турбины (узкие полосы шума и негармонические обертоны 1,7–4 кГц с дрожанием), шипение струи, треск форсажа (буфер редких импульсов). Обороты раскручиваются и сбрасываются с запаздыванием. Спереди слышнее вой, сзади — рёв и треск (по положению камеры; «взгляд назад» это меняет). Сверхзвук оставлен как был. Обтекание — с квадратом скорости, тряска на перегрузке — инфразвуковой гул, у земли (< 300 м) — отражённый рёв и больше реверберации.
- **Разовые звуки:** пушка — непрерывное «бррррт» (шум, нарезанный с частотой ~62 Гц) пока нажат спуск; пуск ракеты — хлопок пиропатрона и уходящий рёв двигателя; взрывы — треск, тело, суббас и разлёт обломков, слышны с задержкой по скорости звука (до 2,5 с), вдали глухие и гулкие; попадание по дрону — металлический удар; ЛТЦ и диполи — разные «выстрелы» кассет; включение форсажа — «вдох» и хлопок; гром — несколько раскатов. Бортовые сигналы (СПО, захват, отсчёт, ИК-ГСН) — через фильтр «гарнитуры».
- **Объёмные голоса** (6): чужие самолёты — рёв/гул/вой/треск форсажа с учётом ракурса, эффект Доплера, поглощение верхов воздухом с расстоянием; ракеты — жёсткий шипящий рёв; заправщики тоже слышны.
- **Окружение:** дождь по обшивке + отдельные капли, гром (теперь и в лобби), рёв у земли.
- **Лобби:** звук включается первым касанием/кликом; камера меняет планы (бок, низкий ракурс сзади с пламенем, сверху, общий план), изредка рядом пролетают самолёты «Подстилки улитки» (иногда парой, с форсажем) или заправщик — со звуком и Доплером; личные рекорды по режимам (`fortuna_drone_stats`: лучший счёт, сбито за вылет, вылеты, точность ракет, флагманы; «Новый личный рекорд!» в итогах); советы (16, сменяются каждые 12 с, тап — следующий). Кнопка звука видна и в меню; в «Настройках» — громкость и «Без звука» (`fortuna_drone_vol`, `fortuna_drone_mute`).

**Итерация 7 — оптимизация, «Кино», объекты на карте.**
- **Рельеф — 8×8 квадратов по 4,25 км с 4 уровнями детализации** (`terrainSeg` в пресете: 16/32/48/64/96 ячеек у ближнего уровня, дальше вдвое реже на каждом уровне; пороги `lodD`). «Юбка» по краю прячет щели между соседями, нормали — по функции высоты (без швов), цвет вершин — по хешу координат (одинаковый на всех уровнях). Два грубых уровня строятся сразу, мелкие — по мере надобности (не чаще одного квадрата за 3 кадра) и выгружаются через ~30 с без использования. Квадраты вне кадра не рисуются.
- **Лес с уровнями детализации:** дальние деревья — упрощённые (конус/многогранник вместо 3 частей), общий буфер матриц с ближней версией; порог `treeHi`. Деревьев стало больше (800/3000/8000/15000/22000), на слабых пресетах квадраты леса крупнее (`treeCell`) — меньше вызовов отрисовки.
- **Замеры** (та же точка, 1500 м / 420 м): «Кино» 2,26 млн → 0,90 млн и 3,96 млн → 1,20 млн треугольников (с тенями); «Средний» 207 тыс. → 73 тыс.; «Низкий» — 30 тыс., 58 вызовов отрисовки.
- **Воздушная перспектива для всех материалов** (`ATMO` и подмена кусков шейдеров three.js в `world.js`): плотность дымки падает с высотой (интеграл exp(−y/1800) вдоль луча, опорная высота 700 м), в сторону солнца дымка подсвечена его цветом (сильнее при низком солнце, в пасмурно — нет).
- **«Ультра»/«Кино»:** вода — PBR с отражением неба и бликом солнца (`waterPBR`); рябь — три слоя шума вместо синусов (без регулярной «сетки»), вдали затухает. **«Кино» без зерна и хроматической аберрации** (зерно удалено полностью), виньетка 0,18, мягче цветокоррекция, самая подробная земля (44 м у ближнего уровня) и лес (22 000), анизотропия текстур.
- **Новые объекты (`games/drone/props.js`):** деревни (6/11/16/20 по пресету, дома со скатными крышами разных цветов, водонапорные башни — два InstancedMesh на всю карту), промзона у города (площадка, цеха, три красно-белые трубы с дымом, резервуары, градирня с паром, фонари в сумерки), дороги между городами, аэродромом, промзоной и деревнями (лента по рельефу с разметкой в шейдере, «притянута» к камере на 0,2 % расстояния — не тонет в рельефе и не мерцает; мосты над водой с опорами), железная дорога через долину (шпалы и рельсы), ЛЭП от промзоны к двум городам (провода с провисом гаснут дальше ~1,5 км), телевышки на холмах с мигающими красными огнями и растяжками, ветряки на гряде (роторы крутятся). Все строения — в `buildings` для столкновений. Объём — по `propsLvl` пресета.
- **Звук:** форсаж мягче (треск без верхов, реже и ниже, шипение струи на форсаже тише, «вдох» без щелчка); пушка — M61 «Вулкан»: поезд импульсов 100 Гц модулирует шум выстрелов и сам звучит как рык, раскрутка блока стволов 40 → 100 Гц за ~0,3 с, выбег с подвыванием, громче.
- **Тесты:** `?mode=training&test=1&touch=1&insets=t,r,b,l,tg` — сенсорный интерфейс и эмуляция выреза/кнопок Telegram на ПК.
- **Кэш и версии модулей.** GitHub Pages отдаёт файлы с `max-age=600`, и браузер мог взять новый `drone.html` со старыми модулями (а новый модуль со старым соседом — вообще не загрузиться). Поэтому у точки входа в `drone.html` и у всех относительных `import` в `games/drone/*.js` стоит `?v=<версия>` (сейчас `20260929d`). **При каждом деплое игры менять версию во всех файлах сразу**, например: `sed -i '' -E "s#\?v=[0-9a-z]+'#?v=НОВАЯ'#g" games/drone/*.js games/drone/sim/*.js` и то же для `drone.html` (с итерации 10 модули есть и в `games/drone/sim/`).

**Итерация 8 — оптимизация, первый заход.**
- **Прогрев шейдеров** (`warmShaders` в `main.js`): все материалы, включая скрытые (пламя форсажа, пули, самолёты противника — скрытая группа `warmGroup`), собираются `renderer.compile` за экраном загрузки (с правильной целью рендера конвейера), после смены погоды с переключением теней — тоже. Первый кадр рисуется до снятия экрана загрузки.
- **Тени:** теневая камера сдвигается за дроном шагами ровно в пиксель карты теней (края не «кипят»). В карту теней лес попадает «теневым набором» — отдельные `InstancedMesh` (слой 3, его видит только теневая камера) с деревьями только в зоне теней вокруг дрона; набор пересобирается при смещении на 120 м или повороте солнца, сами деревья тень не отбрасывают. Дрон, самолёты, ракеты — каждый кадр, как раньше. «Кино» у земли: 1,20 → 0,87 млн треугольников.
- **Рельеф в фоновом потоке:** расчёт высоты и сетки участка — в `terrain-core.js` (без three.js), подробные участки строит `terrain-worker.js` (модульный Web Worker, данные передаются без копирования); без поддержки модульных потоков — в основном потоке, как раньше.
- **HUD на холсте** (`#hudc`): визир, упреждение, ИК-ГСН, метки целей/ракет/заправщиков, стрелки у края (указывают направление), рамка захвата с анимацией, подпись захваченной цели, маркеры попаданий, виртуальный курсор. Блики объектива — свой холст `#flarec` (перерисовывается, только пока солнце в кадре). Панель ракет пишется в страницу, только если её текст изменился. Кнопки и текстовые панели — HTML.
- **Меньше мусора в памяти:** записи СПО, объёмного звука, экранные координаты — из пулов; выбор ближайших ракет для света и голосов звука — без новых массивов; голос звука помнит источник, а не переиспользуемую запись.

**Итерация 9 — второй заход, отдельными настройками (по умолчанию выключены, `perf.halfFx`, `perf.smartQ`).**
- **«Облака и дым в половинном разрешении»** (нужен конвейер кадра и WebGL2): облака-спрайты и облачный слой (`world.setFxLayer`) и дым (`SMOKE`) — на слое `FX_LAYER` (4), огонь и вспышки (`FX`, аддитивные) — на `FX_ADD_LAYER` (5). Конвейер (`post.js`) рисует основной кадр с текстурой глубины (`DepthTexture` 24+8; с MSAA глубина переносится при «разрешении» буфера), затем слой 4 — в буфер половинного разрешения без своей глубины: шейдеры облаков и дыма сами сравнивают глубину с глубиной кадра (`FXU`, `fxSoft`) и мягко растворяются на стыке с землёй и самолётами; затем наложение «над» кадром (премультиплированный цвет) и сверху слой 5 в полном разрешении (иначе дым закрывал огонь). После прохода `FXU.tDepth` обнуляется: текстура глубины прикреплена к буферу кадра, в шейдерах основного прохода её держать нельзя (петля обратной связи). Размер точек дыма в половинном проходе делится на 2.
- **«Умное динамическое качество»** (вместе с динамическим разрешением): при нехватке кадров сначала снижаются уровни детализации `QK = [1, 0.8, 0.65, 0.5]` (`world.setDetail`: дальности подробных уровней рельефа, подробного леса и прорисовки леса), потом разрешение; возврат — сначала разрешение (чёткость), потом детализация. Счётчик кадров показывает «дет. N%» и «FX½».
- **HUD-холст:** подписи — с мягкой тенью, как текст HUD в HTML (`text-shadow 0 0 5px`), вместо жёсткой 3-пиксельной обводки из итерации 8.

**Headless-проверка без браузера:** `tools/drone-headless/run.sh [пресет] [режим] [погода]` — JavaScriptCore из macOS + настоящий three.js r128 (скачивается при первом запуске) + заглушки DOM/WebGL. Прогоняет меню, вылет с ботом 120 с, кадры цикла, обучение, отрисовку вкладок, смену всех погод, окно сравнения апскейлеров и печатает OK/FAIL. Ловит ошибки выполнения и порядка инициализации; **шейдеры не компилирует и картинку не проверяет** — это только в браузере.
