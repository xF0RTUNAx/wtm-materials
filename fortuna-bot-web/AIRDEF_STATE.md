# «Воздушное превосходство» — состояние работы (единая точка правды)

Этот файл читает **каждая** сессия Claude (любой моделью) перед работой над игрой и дописывает в конце работы.
Подробная история — в `SESSION_HANDOFF.md` (разделы с 2026-10-12), правила прокачки — `AIRDEF_PROGRESSION.md`.
Секретов сюда не писать: всё в `main` публично на fortunawtm.com.

## Как начинать сессию
1. Ветка `online-dev` (`git -C /Users/mark./wtm-materials branch --show-current`). Посмотреть `git log --oneline -10` и `git status --short`:
   несохранённые правки — чья-то незаконченная работа; спросить Mark, прежде чем трогать.
2. Прочитать этот файл целиком, затем нужный раздел `SESSION_HANDOFF.md` (поиском, не целиком).
3. Память Claude (папка memory) — общая для всех моделей, если сессия открыта в папке `/Users/mark./инфографика`.

## Правила (обязательные)
- Не трогать, не коммитить и не удалять `fortuna-bot-web/ECONOMY_CATALOG.md`, `fortuna-bot-web/CLAUDE.md`, `fortuna-bot-web/tools/airdef-fx/sheets/`.
- После каждой законченной задачи — строка в журнал ниже, коммит и `git push origin online-dev` (в `main` — нет); строка
  `Co-Authored-By:` — как задаёт Claude Code в сессии. Пуш в `online-dev` нужен, чтобы работу подхватила любая сессия, в том числе облачная.
  В `main` — только по слову Mark «деплой», процедура — навык `/deploy-airdef`.
- Секреты (LOG_KEY, токены ботов, токен Supabase) — никогда в чат и в репозиторий; Supabase — Mark логинится сам (`supabase login`).
  CLI в `fortuna-bot-web` берёт старый токен из `.env` — команды с префиксом `SUPABASE_ACCESS_TOKEN=`.
- Тестовые аккаунты на боевом Supabase не создавать; функции базы проверять в блоке `do $$ … raise exception 'ИТОГ …' $$` (откат).
- Модели: только CC0 / CC BY, без игровых рипов (смотреть описание и имена материалов); не ужимать сильно (`target` в prepare.js — щадяще).
- После правок — ссылки Mark: localhost `:8935/fortuna-bot-web/games/airdef.html`, LAN `192.168.68.102:8935/…`, сайт после деплоя;
  интерфейс проверять и в горизонтальной ориентации телефона (932×430, отступ Telegram `--tg-t: 46px`).
- Правки `game-server/` и файлов, которые он импортирует (`games/airdef/arsenal.js`, `progress.js`, `launchers.js`, `sim/*`), после
  деплоя требуют от Mark `update.ps1` на ноутбуке.

## Кто что делает (главная сессия и помощники)
Mark работает с **Opus на высоком усилии** — он руководитель: решает, раздаёт задачи помощникам, ждёт ответа, проверяет и правит.
Помощники — `.claude/agents/` в репозитории (на Mac в `~/.claude` — ссылки), все на высоком усилии, чат не видят: задание им —
полностью (цель, файлы, что нельзя трогать, как проверить, что вернуть).

| Помощник | Модель | Для чего |
|---|---|---|
| `airdef-scout` | Haiku | поиск моделей, текстур, звуков с проверкой лицензии; поиск мест в коде, когда их много |
| `airdef-tester` | Haiku | прогон тестов и стендов, в чат — только итог |
| `airdef-worker` | Sonnet | основной код по готовому плану, объёмные однотипные правки, подготовка моделей по рецепту |
| `airdef-reviewer` | Opus | независимая проверка большого диффа перед деплоем |

Сам Opus: проектирование и решения с Mark, сложные баги, правки на 1–2 места (их дешевле сделать, чем описать), итоговая проверка
работы помощников (дифф, тест, снимок). Пока помощник правит файлы, главная сессия их не трогает.

Облако видит только GitHub: репозиторий клонируется заново, ветку переключить на `online-dev` (`git checkout online-dev && git pull`).

`deno` (если в облаке есть deno — иначе сказать Mark), документов. Деплой из облака — только статика (пуш в `main` по «деплой»);
функции Supabase и модели — с Mac. Перед концом облачной сессии — журнал и пуш в `online-dev`.
