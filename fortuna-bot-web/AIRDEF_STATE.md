## Свои модели оружия: подмена в игре
Свои модели оружия строит только сборщик — чат на Sonnet 5.5 (его инструкция и рецепт лежат рядом с моделями, в `~/Downloads/Воздушное превосходство/Модели/Свои/`; если Mark пишет «собираем <название>»
и ты Sonnet 5.5, ты сборщик — прочитай `Свои/CLAUDE.md`, в какой бы папке ни был открыт чат). Fable и Opus моделей не строят, не открывают, не сравнивают с картинками и ничего по ним не ищут.
Когда Mark говорит «модель <название> готова», нужна только подмена:
1. В `fortuna-bot-web`: `deno run -A tools/airdef-models/integrate-own.js "<папка модели в Свои/>"` (`--dry` — только план). Скрипт читает один файл — `ПАСПОРТ.json` в папке модели — и сам копирует файлы в
   `tools/airdef-models/own/`, меняет запись ключа в prepare.js, собирает файл игры, поднимает версию файла в блоке `GLB_V_OWN` (models.js), убирает файл из авторов чужого набора и снимает миниатюру.
   В конце он печатает, какие пути коммитить.
2. Как после любой правки игры: тесты через airdef-tester (ui-test, event-test, sim-test), строка в журнал, коммит только перечисленных путей, пуш в `online-dev`.
Больше по модели ничего не нужно: превью, чертежи, отчёт и пакет для Sketchfab — дело сборщика и Mark. Если после подмены Mark что-то не нравится в игре, он говорит об этом сборщику, затем снова «модель … готова».
Git — у основного чата, Blender — у сборщика. Mark может и сам, в терминале, без чата: тот же скрипт с `--commit --push` (коммит только перечисленных путей с нейтральным сообщением и пуш в `online-dev`);
в чате коммитить вручную, без `--commit`.
Техника (ЗСУ и т. п.) собирается тем же способом, но подменяется вручную (integrate-own.js — только для оружия). Образец — Flakpanzer Gepard (2026-10-22): `tools/airdef-models/own/gepard.glb` и `own/gepard-build/` (build.py, bake.py, rig.py, deliver.py),
записи `gepard` / `gepard_lo` в prepare.js (unit, own, `nTex` — карта нормалей, hinge, groups по именам объектов; `_lo` — 8 тыс. треугольников, без нормалей), оси tp / cp в launchers.js (их печатает prepare.js), META.gepard.camo `{ tex: true, detail: true }` и версии в GLB_V_OWN (models.js).
Карта нормалей — только у ближней модели (на телефоне ≤ 512), зернистость краски (`camo.detail`) — шейдером по координатам модели, без файлов. Для сравнения в адресе: `?nrm=0` (без нормалей), `?det=0` (без зернистости).

## Кто что делает (главная сессия и помощники)
Mark работает с **Opus на высоком усилии** — он руководитель: решает, раздаёт задачи помощникам, ждёт ответа, проверяет и правит.
Помощники — `.claude/agents/` в репозитории (на Mac в `~/.claude` — ссылки), все на высоком усилии, чат не видят: задание им —
полностью (цель, файлы, что нельзя трогать, как проверить, что вернуть).

| Помощник | Модель | Для чего |
|---|---|---|
| `airdef-scout` | Haiku | поиск моделей, текстур, звуков с проверкой лицензии; поиск мест в коде, когда их много |
| `airdef-tester` | Haiku | прогон тестов и стендов, в чат — только итог |
| `airdef-worker` | Sonnet | основной код по готовому плану, объёмные однотипные правки, подготовка моделей по рецепту |
| `airdef-reviewer` | Opus | независимая проверка большого диффа перед деплоем |

Сам Opus: проектирование и решения с Mark, сложные баги, правки на 1–2 места (их дешевле сделать, чем описать), итоговая проверка
работы помощников (дифф, тест, снимок). Пока помощник правит файлы, главная сессия их не трогает.
