# Онлайн «Симулятора Летки» — ТЗ и план

Согласовано с Mark 2026-09-29. Этот файл — источник истины по онлайн-режиму. Решения ниже приняты, менять только по его просьбе.

## Решения

| Вопрос | Решение |
|---|---|
| Форматы | 1×1, 2×2, 3×3, 4×4 |
| Правила | Командный бой с возрождением: 5 мин, возрождение ~5 с, побеждает команда с бо́льшим числом сбитых |
| Режимы | **Аркада и Реализм — раздельно**: свои очереди, свои лобби; каждый видит, что в режиме кто-то ищет игроков |
| Боты | Пустой слот можно отдать боту (например, трое → 2×2 с ботом или трое против трёх ботов) |
| Старт | Только когда **все живые игроки лобби нажали «Готов»**. Вышел — отметка сброшена, старт ждёт |
| Лобби | Создатель выбирает режим и формат, зовёт по коду/ссылке (удобно в Telegram), может переставлять игроков и слоты ботов; игроки сами меняют команду |
| Быстрый поиск | Сервер собирает лобби из очереди режима → всем «Бой найден — подтвердить» (15 с); не подтвердил — выпадает |
| Доступ | Только зарегистрированные (ник аккаунта сайта) |
| Награды | Пока нет. В конце — экран итогов (сбитые, попадания, лучший пилот) |
| Сервер | Deno (как edge-функции Supabase; один exe на Windows, встроенный WebSocket) на Windows-ноутбуке с ботом (служба NSSM рядом с ботом) + Cloudflare Tunnel → постоянный `wss://game.fortunawtm.com` (домен уже на Cloudflare, порты не открываем, IP скрыт). Код переносим на VPS без изменений |

Отвергнуто: Supabase Realtime (сообщение считается 1 раз при отправке + по разу на каждого получателя → ~384 тыс. сообщений за бой 4×4, бесплатного лимита 2 млн/мес хватает на ~5 боёв); P2P (NAT на мобильных, падение хоста).

## Сетевая модель

- **Свой самолёт** — у игрока, без задержки (как сейчас). Клиент шлёт состояние 20 Гц: позиция, скорость, углы, газ/форсаж, команды ручки. Сервер проверяет правдоподобие (скорость, перегрузка, телепорты) по той же лётной модели.
- **Чужие самолёты** — интерполяция снимков с отставанием ~100 мс, короткая экстраполяция при потере пакетов.
- **Ракеты, ловушки, урон, счёт — на сервере.** Пуск: клиент шлёт «хочу пуск ключ/цель», сервер проверяет подвеску, перезарядку, захват (ИК-ГСН / РЛС) и создаёт ракету. Клиенты рисуют ракету по снимкам сервера (10–20 Гц) с локальным досчётом той же физикой. ЛТЦ/диполи — событие игрока, сервер решает увод ракет.
- **Радар:** захват — сообщение серверу; у цели СПО показывает «захват», при пуске — «пуск».
- **Пушка:** попадание фиксирует стреляющий (честнее при пинге), сервер перепроверяет по истории позиций цели (~300 мс) и дальности/углу.
- **Обрыв связи** (свернул Telegram и т. п.): самолёт ведёт бот; вернулся в течение 60 с — продолжает. Свёрнутая вкладка не рвёт связь, но перестаёт слать состояние (браузер останавливает кадры) — поэтому бот берёт самолёт и после ~1 с молчания, а не только после обрыва.
- Такт сервера 30 Гц, снимки клиентам 20 Гц. Трафик 4×4 ≈ 0,6 Мбит/с на выгрузку.

## Авторизация

На сайте личность = `player_id` (UUID из `auth-password`, наружу не отдаётся). Перед входом в онлайн клиент вызывает новую edge-функцию `mp-ticket` (`player_id` → `{player_id, login, exp}` + HMAC-подпись общим секретом). Игровой сервер проверяет подпись и срок, ник берёт из билета. Секрет: в Supabase secrets и в env сервера на ноутбуке.

### createBattle(ctx) — как хозяин боя подключается к логике
`ctx = { mode(), opponents(owner), targetable(t), canAct(owner), hurt(t, amount), sunDir, sunVis(), fx: {…хуки} }`.
Аппарат-человек: `human: true`, `radar {contacts: Map, lock, lostT, scanT, t}`, `flares/chaff`, `rcs()`; урон по нему не считается внутри battle, а уходит в `ctx.hurt` (у клиента — `hurt()` игрока или заявка серверу `MP.hitRemote`). Аппарат ИИ: `S` (из `AC`), `tgt` (цель = ближайший живой противник, `pickTarget`), `stt` (РЛС сопровождает `tgt`), `cmFlare/cmChaff`, `msl` (подвеска `[{key, mesh?}]`), `team` (по умолчанию 1). `lockedOn(o, t)` — единая проверка «РЛС o ведёт t» для человека и ИИ. Пули с `dmg 0` — только трассеры.
Хуки `fx` (все необязательные): `launchPos, launched, motor, trail, pitbull, detonated, missileResult, cmEmpty, cmDrop, lockBroken, cm, hit, killed, shot, bulletHit, bulletOff, spawned, aiVisual, radarLost` — вызываются ровно там, где раньше стоял код эффектов (порядок `Math.random` сохранён; проверка — `tools/drone-headless/regress.sh`).
Клиент подменяет позицию ракеты/пули на `mesh.position` (модель двигается напрямую), поворот ракеты — после `updateMissile` в `tick`.

### Протокол (JSON по WebSocket)
Клиент → сервер: `hello {name, pid | ticket}` · `create {mode, size}` · `join {code}` · `leave` · `team {team}` · `ready {on}` ·
`st {s:[x,y,z,yaw,pitch,roll,speed,thr,flags]}` 20 Гц (flags: 1 форсаж, 2 стреляет) · `hit {target}` (попадание пушки) · `self {dmg}` (удар о землю/здание) ·
`load {l:[8 ключей|null]}` (подвеска, один раз на жизнь — после `start` и своего `spawn`) · `lock {target|0}` (захват РЛС / сброс) ·
`launch {key, target|0, slot, s}` (пуск; `s` — своё состояние в момент нажатия) · `cm {type:'flare'|'chaff'}`.
Сервер → клиент: `welcome {id,name}` · `err {msg}` · `room {code,mode,size,host,state:'lobby'|'countdown'|'play'|'end',left,score,players:[{id,name,team,ready,k,d}]}` ·
`start {seed,weather,mode,cd,len,spawns:{id:[x,y,z,yaw]}}` · `snap {T, P:[[id,alive,hp,...s(9),lock]], M:[[mid,x,y,z,dx,dy,dz,speed,flags,target,closing]]}` 20 Гц
(`lock` — id того, кого ведёт РЛС игрока, 0 — никого; у ракеты flags: 1 двигатель, 2 активная ГСН, 4 потеряла цель/уведена; closing — сближение с целью, м/с, или null) ·
`ml {id,key,owner,target,slot,p:[x,y,z]}` (пуск) · `mx {id,hit,p}` (подрыв) · `cm {id,type}` (ловушки игрока id — всем, кроме него) · `lockx {why:'lost'|'chaff'}` (сервер снял ваш захват) · `deny {msg,slot}` (пуск отклонён) ·
`hp {id,hp,by}` · `kill {victim,killer,by,score}` (by — «ПУШКА», «ЗЕМЛЯ» или название ракеты) · `spawn {id,s:[x,y,z,yaw]}` · `gone {id}` · `end {score, players:[{id,name,team,k,d}]}`.
Проверки на сервере: состояние — конечные числа в пределах карты и скорость < 1500 м/с (`validState`); попадание — оба живы, разные команды, дистанция ≤ 2200 м, нос стрелка в пределах 25° от цели, ≤ 25 заявок/с; урон пушки = `GUN_DMG × MODES[mode].dmgTaken`. Разбился сам — очко команде соперника. Старт — все в комнате «Готов» и в обеих командах ≥ 1 человек.

### Ракеты, ловушки, РЛС на сервере (этап 2, как сделано)
- На комнату — `createBattle(ctx)` из `sim/battle.js` (тот же код, что в одиночной игре). У каждого игрока на одну жизнь — прокси `makeCraft({human:true, cid, team, ...DRONE, flares/chaff = MODES[mode].cm, radar, load})`; после сбития — новый прокси (старые ракеты на возродившегося не наводятся). Позиция прокси — из `st`, между состояниями — по прямой ≤ 0,3 с. `opponents` — массив команды соперника (`r.sides`), `ctx.hurt(t, amount, by, msl)` → урон игроку, сбитие — хозяину ракеты. Солнце — `sunFor(погода)`.
- Такт 20 Гц, внутри 2 шага по 25 мс: `updateRadar` каждого прокси, `updateMissile`, `updateCMs`.
- Пуск: ракета есть в `load[slot]`, перезарядка 0,4 с, ИК — `irCanSee` по прокси с конусом max(fov, slaved) + 5° (запас на задержку сети; без цели — только у `loal`), ПАРЛ — `radar.lock` на цели, АРЛ — захват, свежая отметка обзора или `radarSees`. Иначе `deny`.
- Захват: `lock` ставит `radar.lock` прокси, дальше его ведёт та же логика РЛС (цель вне обзора > 0,8 с — `lockx lost`; диполи цели — `lockx chaff`). Он же подсвет ПАРЛ, радиокоррекция АРЛ и СПО цели (поле `lock` в снимке).
- ЛТЦ/диполи: `battle.dropCM(прокси)` — счётчики, увод ракет, срыв захватов на сервере; остальным — `cm` для картинки.

### Этап 3: боты, подхват, переподключение, быстрый поиск (как сделано)
- **Запись участника** (`rooms.js`): одна на место в комнате — человек (`ws`, `null` — нет связи) или бот (`bot: true`). `p.ai` — самолётом сейчас правит ИИ сервера.
- **Боты** — аппараты ИИ из `battle.js` на «Изделии»: `botSpec(mode)` (поля как у `AC`: `DRONE`, перегрузка/угловая скорость режима, `radarR = RADAR.range`, `skill` 0,75 × `aiSkill` режима, ЛТЦ/диполи режима), подвеска — случайная из `BOT_LOADOUTS` (проверяются `validLoadout`). В `battle.js`: `spawnCraft(type, S, lo, …)` и `aiFields` (из `spawnAI`, порядок `Math.random` прежний), флаг `mp` — урон по онлайн-аппарату ИИ идёт в `ctx.hurt` (корпус и сбития ведёт сервер, урон × `dmgTaken`, как по человеку), `damage(…, src)` — кто стрелял из пушки, `fx.aiCM` — ловушки ИИ (остальным — `cm`), `ctx.retarget` — ИИ онлайна перепроверяет ближайшую цель раз в 3 с. Пули ИИ считает сервер (`updateBullets`), в снимке у бота флаг «стреляет» — клиенты рисуют трассеры. Врезался в землю — `fx.killed` → «ЗЕМЛЯ».
- **Лобби:** создатель — `bot {team}` («+ бот»), `kick {id}` (убрать бота), `move {id}` (перевести в другую команду). Боты всегда «Готов». Старт — все люди «Готов» (и на связи), в каждой команде кто-то есть; хватает одного человека и ботов. Вход по коду — и в идущий бой: свободное место или место бота из команды, где людей меньше (бот уходит, `gone`); вошедшему — `start` с `resume {t, score}` и `cd` 0.
- **Подхват ИИ:** нет `st` дольше 1 с (свёрнутая вкладка/Telegram) или сокет закрылся — `toAI`: тот же объект аппарата получает поля ИИ (`aiFields`, подвеска — что осталось, ловушки — сколько осталось), ракеты по нему продолжают наводиться. Игрок снова шлёт `st` — сервер присылает `you {n, s, hp, load, flares, chaff}` (раз в секунду, пока нет ответа), клиент ставит самолёт туда и отвечает `back {n}` — `toHuman`.
- **Обрыв связи:** в бою место держится 60 с (в комнате `away`), самолёт ведёт ИИ. `hello {…, resume: 1}` с тем же `pid` — новая связь занимает прежнюю запись (тот же `id`), приходит `start` с `resume {t, score, you}`; нет места — `noresume`. Клиент в бою сам переподключается каждые 2 с до 55 с («НЕТ СВЯЗИ · переподключение N с»), потом — в меню. Не вернувшиеся к концу боя выбывают. Открыть игру заново тем же аккаунтом в течение 60 с — тоже возврат в бой.
- **Быстрый поиск:** `queue {mode}` / `unqueue`; очередь по режиму отдельно; двое и больше — через 8 с после второго (восемь — сразу) всем `found {mode, n, T:15}`; `accept`/`decline`; все подтвердили — комната `quick` (size = ⌈n/2⌉, пустые места — боты, все «Готов», старт); кто не подтвердил за 15 с — выпадает из очереди (`unqueued {why}`), подтвердившие ждут дальше. «Кто ищет»: `search {arcade, real}` всем вне комнат и `/health` → `searching`.
- Протокол этапа 3 — клиент → сервер: `bot {team}` · `kick {id}` · `move {id}` · `queue {mode}` · `unqueue` · `accept` · `decline` · `back {n}` · `hello {…, resume}`; сервер → клиент: `search {arcade, real}` · `queued {mode}` · `unqueued {why}` · `found {mode, n, T}` · `accepted {n, of}` · `you {n, s, hp, load, flares, chaff | dead}` · `noresume` · `welcome {…, resumed}`; в `room.players[]` — `bot`, `away`, `ai`, в `room` — `quick`; в `end.players[]` — `bot`.

### Клиент этапа 2
- Сетевые ракеты (`net: true`) лежат в общем `missiles` (их видят HUD, СПО, датчик пуска, звук, свет); в `tick` для них вместо `updateMissile` — `MP.stepMissile`: последний снимок + скорость × прошедшее время (≤ 0,5 с), расхождение гасится за ~0,2 с; своя ракета стартует с пилона (`mpNetLaunched`), пилон снимается только по `ml`. Нет снимков > 1,5 с — ракета убирается.
- `launchPlayerMissile` в онлайне делает те же проверки и шлёт `launch` (`MP.launch`); свои ЛТЦ — `dropCM` с `ctx.remoteCM` (только картинка + `cm` серверу); чужие — `B.spawnCMs`. Захват отправляется при каждой смене `radar.lock` (`MP.lockSent`). У соперника `c.stt`/`c.radar.lock` — из снимка (СПО: захват, пуск ПАРЛ/АРЛ, «М»).
- `sim/battle.js`: `ctx.hurt` получает `by, msl`; выделена `spawnCMs`; `ctx.remoteCM` — одиночная игра не изменилась (`regress.sh`).

### Клиент (online-client.js ↔ main.js)
`createOnline(K)` — K: `G, player, enemies, testName, popup, tabEl, syncMenu, backToMenu, goPlay, countdown, startOnline, setHull, hitMark, meDown, meUp, makeRemote, remoteDown, remoteUp, removeRemote, remoteVisual, remoteShot, showEnd, firing`.
Чужой самолёт — `makeCraft({remote:true, human:true, team, S:{name, code:'ИЗ', radarR, rcs:1.6…}, radar…})`; соперники кладутся в `enemies` (их видят радар, ИК-ГСН, прицел, HUD, звук), союзники — в `MP.allies` (голубые метки с ником). Интерполяция: `MP.srvT` подтягивается к `T` снимков, показ на `INTERP = 0.12 с` в прошлом, после последнего снимка — экстраполяция ≤ 0,35 с. В `tick`: `MP.update(dt)` первым; в онлайне не идёт расписание противников, нет конца вылета по времени/топливу (топливо не тратится, `MODE = {...MODES[mode], fuelBurn: 0}`), `updateAI` пропускает `remote`. `hurt()` в онлайне = заявка `self` серверу; корпус приходит в `hp`. Пауза в онлайне — только меню (мир не останавливается), `visibilitychange` паузу не ставит. Вкладка «Онлайн» скрыта в партии на награду (без `?mode=training`). Ракеты — с этапа 2 (ниже).
Адрес сервера (`serverUrl`): на `fortunawtm.com` → `wss://game.fortunawtm.com/ws`, иначе `ws://<тот же хост>:8787/ws`.

## Заметки к следующим этапам (продуманные решения)

**Этап 2 — ракеты, ловушки, РЛС/СПО по сети.**
- Сервер держит на комнату `createBattle(ctx)`: аппараты людей — прокси `makeCraft({human:true, team, radar…})`, позиция/углы/скорость/`ab` обновляются из `st` (для `seekerHeat` важны `ab` и курс). `opponents` — по командам (массивы на команду), `ctx.hurt` = урон по игроку с `hp`/`kill`, `fx` — рассылка событий.
- Пуск: клиент шлёт `launch {key, target, slot}`; сервер проверяет, что ракета есть в подвеске игрока (подвеску клиент сообщает при старте/возрождении, сервер проверяет `MAX_LOAD`/`canMount` как в main.js), перезарядку 0,45 с, для ИК — `irCanSee` по прокси, для ПАРЛ — захват РЛС (`lock`), для АРЛ — захват или свежий контакт; затем `battle.launchMissile`. Ракеты считаются на сервере с тем же `updateMissile` (такт 30 Гц), в снимки — `M:[[mid,key,x,y,z,dx,dy,dz,flags(motor,active,lost)]]`; клиент кладёт «сетевые» ракеты в `missiles` (поля `M, t, pos, dir, owner, target, lost, active, closing, dPrev` — их читают HUD, СПО, датчик пуска, плашка угрозы), `updateMissile` для них не зовёт, двигает по снимкам с досчётом `dir×speed`.
- Захват РЛС: клиент шлёт `lock {target|null}` (после `cycleLock`/потери), сервер хранит в прокси `radar.lock` → `lockedOn` для ПАРЛ и СПО цели; в `snap` — кто кого ведёт, СПО клиента (`updateRwr`) берёт `stt` соперников из этого.
- ЛТЦ/диполи: `cm {type}` → `battle.dropCM(прокси)` (срыв захвата, увод ракет — на сервере), событие остальным для эффектов.
- Детерминизма между клиентом и сервером не нужно: сервер — авторитет, клиент только рисует.

**Этап 3 — сделан** (как — ниже, «Этап 3: боты, подхват, переподключение, быстрый поиск»).

**Этап 4 — прод: сделан в коде** (как — ниже, «Этап 4: билеты, приглашения, сервер на Windows»); осталось развернуть — см. «Запуск в прод».

### Этап 4: билеты, приглашения, сервер на Windows (как сделано)
- **Билет** — `supabase/functions/mp-ticket`: `{player_id}` → игрок из `players` → `{ticket}` = `base64url(JSON{pid, login, exp: now+600}) + '.' + base64url(HMAC-SHA256(MP_SECRET, первая часть))`; без `MP_SECRET` — 503 «Онлайн ещё не настроен». Игра берёт билет при каждом подключении (`online-client.js::fetchTicket`, адрес — `CONFIG.MP_TICKET_URL` из `config.js`, который теперь грузит `drone.html`) и шлёт `hello {ticket}`; сервер с `MP_SECRET` пускает только по билету, ник — из билета. `pid` из билета — ключ возвращения в бой. Тест-ники (`mpname`, `test-…`) билет не берут.
- **Сервер наружу:** `HOST` (служба — `127.0.0.1`, снаружи только туннель), не больше `MAX_CLIENTS` (400) связей, 300 комнат, сообщения длиннее 4 КБ не разбираются, больше 120 в секунду с одной связи — выбрасываются, больше 600 — связь закрывается.
- **Приглашение:** в комнате «пригласить» — в Telegram «поделиться» в чат (`openTelegramLink` t.me/share), на телефоне — системное меню, на ПК — ссылка в буфер (`https://fortunawtm.com/play#mp=КОД`). Сайт (`js/app.js`): `#mp=КОД` запоминается в `sessionStorage` (`mp_invite`), на экране входа — подсказка «Вас пригласили…», после входа игра открывается сама (`drone.html?mode=training&mp=КОД`): вкладка «Онлайн», вход в комнату. `?mp=1` — только открыть вкладку «Онлайн» (кнопка «Онлайн-бой» на карточке игры). Под карточкой — «Онлайн: в игре N · ищут бой…» из `game.fortunawtm.com/health` (сервер недоступен — строки нет). Фрейму игры добавлены `clipboard-write; web-share`.
- **Windows:** `game-server/windows/` — `install.ps1` (Deno, NSSM, секрет в `C:\ProgramData\FortunaGame\mp_secret.txt`, служба `FortunaGame`, журнал `logs\server.log`), `tunnel.ps1` (Cloudflare Tunnel `fortuna-game` → `game.fortunawtm.com`, служба `FortunaTunnel`), `update.ps1` (`git pull` + перезапуск, спросит, если кто-то играет), `README.md` — пошагово. Скрипты в UTF-8 с BOM (иначе Windows PowerShell 5.1 портит русский текст); синтаксис проверен PowerShell 7 (в облаке), запуск на Windows — не проверен.

### Запуск в прод (порядок)
1. Ноутбук: код (`git clone` c sparse-checkout — `game-server/windows/README.md`, шаг 1), `install.ps1` → служба и секрет.
2. Мак: `supabase secrets set MP_SECRET=<секрет с ноутбука>` и `supabase functions deploy mp-ticket --no-verify-jwt` (из `fortuna-bot-web/`).
3. Ноутбук: `tunnel.ps1` → проверить `https://game.fortunawtm.com/health`.
4. Деплой сайта: `online-dev` → `main` (только по «деплой» от Mark; версия модулей уже `20260929d`). До шагов 1–3 вкладка «Онлайн» на сайте покажет «Сервер онлайна сейчас недоступен» — остальная игра работает как раньше.
5. На ноутбуке после деплоя — `git checkout main` уже стоит; дальше обновления — `update.ps1`.
